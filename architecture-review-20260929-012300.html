Problem: the list of live pages per locale is written out in six or more places, so the sitemap, llms.txt and the redirect exclusions can drift without any test failing.

Solution: one module knows every live page for each locale (URL, alternates, sitemap data), and routes, the sitemap, llms/robots, hreflang and LegacyRedirects all read from it.

  • Locality: adding a page is one edit
  • Leverage: one interface, five callers
  • Tests hit the registry, not scraped HTML
  • llms.txt service list stops duplicating

Problem: name, email, phone, KvK and BTW live in three config files, and derived facts (the tel: link, the schema.org organisation) are rebuilt by each caller.

Solution: one Organisation module owns every fact, including the derived ones, and every caller reads from it.

  • Locality: phone changes in one place
  • Leverage: footer, JSON-LD, llms share it
  • Tests read values, not rendered HTML

  • Locale parity test becomes trivial
